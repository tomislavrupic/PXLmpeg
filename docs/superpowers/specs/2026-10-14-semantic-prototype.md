# First semantic search prototype

Build an optional native Swift/Core ML module and `pxl-search` developer CLI. The existing processing/playback libraries keep zero external dependencies and do not import analysis. Select one compact matching image/text model pair and compare a smaller candidate on the same real footage. Prefer original MobileCLIP-S2 for quality, with S0 as a lightweight baseline, subject to actual model admission and performance.

Models and tokenizer data are downloaded explicitly into ignored developer storage, pinned by upstream revision and SHA-256. They are not added to Git or loaded by the core. Preserve the selected original model card and its linked license provenance; newer MobileCLIP2 licensing/model representations are a separate choice. Implement tokenizer and search in original Swift, no foreign runtime/package source embedded.

Index local supported MOV/MP4 via existing strict metadata admission, with explicit Rec.709 interpretation for known untagged ALi SDR. Sample sequentially at a chosen interval with a hard sample cap (default 256, absolute 4096), and one in-flight image/inference. Use core required-hardware VideoToolbox with canonical YUV metadata for BT.709 SDR, on a dedicated blocking queue. Use AVAssetImageGenerator preferred transform and explicit force-SDR for tagged HDR. Both feed documented aspect-preserving resize and center crop to sRGB. Record the actual backend per source. This is a model derivative representation, not HDR export/tone-map approval or the custom VT/Metal transcode graph. Record requested and actual timestamps and gaps. Source content hash before/after detects changing media. Do not rewrite originals.

Sidecars identify schema, source digest/descriptor, sampling/truncation, preprocessing version, matching image/text/tokenizer identity, compute policy, timing measurements and normalized embeddings. Publish to a new destination only; reject overwrite, incompatible model/tokenizer/preprocessing, malformed/nonfinite/zero vectors and oversized index/query/sample requests. Similarity is a ranking score, not probability. No captions or temporal action claims. Sparse image sampling can miss brief actions and center crop can omit edge subjects.

Query text -> matching text encoder -> normalized cosine ranking -> source URL and actual sample timestamp. Keep samples distinct initially rather than inventing continuous action spans. Library provides cooperative cancellation between native operations and refuses concurrent work per analyzer. Cancellation cannot hard-stop an in-flight OS prediction. The host owns access lifetime, catalogs and playback/UI.

Profile CPU-only, CPU+ANE and all compute configurations. Report MLComputePlan per-operation preferred/supported counts and estimated cost-weight coverage separately from measured runtime data. Capture process-scoped xctrace Core AI/Neural Engine events where available. Report what the trace actually measures (operations/events/durations), not a fabricated 'percent of inference on ANE' from enabled flags or speedup. If runtime visibility is unavailable, preserve the trace/error and report the exact limitation.

Acceptance: native tokenizer conformance vectors, Unicode/punctuation/length limits, ranking and malformed-index tests, exact-time/orientation/SDR sampling tests, real model identity mismatch and cancellation tests, real ALi plus iPhone indexing/search with inspected sample frames and reproducible queries. Measure index cost and warm image/text inference latency; keep model loading/compilation and instrumentation overhead separate. Preserve source hashes. Full regression/build/dependency audit, independent whole-change review and scoped publication under the existing user authorization.
