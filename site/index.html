01 / The idea

A smaller foundation.
A wider possibility.

PXLmpeg is a native media-processing engine for M-series Macs. It brings hardware video engines, original Metal kernels, and explicit media contracts into one reusable Swift package.

The first intended production consumer is Pixel Deck. We’re building toward professional codec support and precise native frame/audio delivery, while keeping semantic search optional. Today’s proven media paths remain focused on H.264 and HEVC.

The direction / target architecture

One engine.
Picture, sound and understanding.

PXLmpeg supplies media. Pixel Deck owns colour, monitoring, clocks and output. Analysis branches off the frame path, so searching never becomes a requirement for playback.

ENGINE
Early research phase

Early days.
Deliberate steps.

This is a research project in active development. The API is evolving, the format matrix is focused, and each new capability needs evidence.

We’re testing real footage and native hardware paths. Professional formats, full FFmpeg compatibility and calibrated HDR display validation remain ahead. The native search UI is a separate draft; a reported whole-Mac stall is still under investigation.

03 / On the workbench

Professional media first.

The next engine milestone is ProRes MOV + PCM, with the frame and audio contract Pixel Deck needs. These are implementation targets, not announced codec support.

  • NextProRes + precise native delivery

    Start with ProRes 422 HQ and PCM. Preserve 10-bit 4:2:2 precision, timestamps and bounded buffers; prove seeking, cancellation and audio sync.

  • ResearchSony MXF / XAVC

    Inspect real camera profiles early. Verify container, codec and native backend support separately before promising acceleration.

  • DraftSearch a moment. Jump into playback.

    The native Mac search UI shows visual matches and thumbnails with click-to-seek playback. It remains a research build while stability is investigated. No production download is offered.
